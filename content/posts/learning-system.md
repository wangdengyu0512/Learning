学习一个新主题时，最容易做的事是不断增加输入：收藏更多教程、关注更多作者、打开更多标签页。输入带来忙碌感，却不一定带来理解。

## 从问题而不是资料开始

我会先写下一个尽可能具体的问题。例如，不写“学习 Next.js”，而是写：

- 静态网站如何部署到 GitHub Pages？
- 动态文章路由怎样在构建阶段生成？
- 怎样让新增一篇文章只需要创建一个 Markdown 文件？

问题越具体，学习的边界越清楚，也越容易验证是否真的学会。

## 用输出检查理解

一次有效的学习至少应当留下某种输出。它可以是一段代码、一张图、一篇短文，或者对另一个人的解释。

我常用的最小闭环是：

1. 写下当前理解；
2. 做一个足够小的实践；
3. 记录预期与结果的差异；
4. 用自己的话重新解释；
5. 隔一段时间再次使用。

其中最重要的不是笔记是否漂亮，而是它能否帮助下一次行动。

## 给知识留下上下文

孤立的结论很容易过期。有价值的记录通常还包括：当时要解决什么问题、有哪些限制、为什么没有选择另一个方案。

所以比起只写“怎么做”，我更希望记录“为什么在这个场景下这样做”。上下文让知识不仅能够被搜索，也能够被判断。

这套方法仍在变化。学习系统不应该成为另一件需要维护的复杂工具；它唯一的目标，是让我更可靠地从不知道走向会使用。
