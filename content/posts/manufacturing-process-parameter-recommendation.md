# 工艺参数推荐：从经验试调到数据、知识与机理驱动的闭环决策

一家工厂准备生产一款新产品。

工艺工程师拿到产品图纸、材料牌号和质量要求后，首先从相似产品的工艺卡中找出一套参数：设备温度设为多少，压力多大，速度多快，每个阶段持续多长时间。首件完成后，尺寸超差；工程师降低速度、延长保压，再做一件。第二件尺寸合格，但表面出现缺陷；工程师继续调整温度和压力。经过多轮试调，产品终于进入可生产状态。

这套做法在制造现场十分常见。它并不意味着工程师缺少能力，恰恰相反，经验丰富的工程师往往能够把材料特性、设备差异、产品结构和历史问题综合起来，快速收敛到一个可用方案。

真正的问题在于，这种能力很难规模化：

- 相同任务交给不同工程师，可能得到不同参数；
- 经验散落在个人记忆、工艺卡、试验报告和聊天记录中；
- 新材料、新设备和新产品出现后，旧经验不一定仍然适用；
- 参数调整往往同时影响质量、节拍、能耗、成本和设备寿命；
- 一次试调成功，不代表参数对后续批次、其他设备或环境变化仍然稳健；
- 现场知道最终用了什么参数，却未必完整记录为什么调整、调整前后发生了什么。

于是，企业开始尝试用数据和算法回答一个看似直接的问题：

> 给定当前产品、材料、设备、环境和质量目标，工艺参数应该怎样设置？

但这个问题并不能通过训练一个质量预测模型就自动解决。预测模型可以估计“使用这组参数可能得到什么结果”，优化算法可以寻找“目标函数下数学意义上的最优点”，现场真正需要的却是一套**满足工艺约束、风险可控、能够解释、允许工程师干预，并能通过生产结果持续修正的参数决策方案**。

这才是工艺参数推荐。

本文将沿着下面这条主线展开：

```text
制造上下文与历史案例
  → 识别关键参数和适用边界
  → 建立参数到质量、成本和效率的映射
  → 在工艺约束内生成候选方案
  → 评估收益、不确定性与风险
  → 向工程师解释并推荐
  → 受控执行与质量验证
  → 更新数据、知识和模型
```

> 资料口径：本文根据截至 **2026 年 10 月 19 日**可访问的公开论文整理。文中的系统架构和实施路径用于建立通用方法，不代表任何行业都可以跳过工艺验证，让模型直接控制生产设备。

## 一、先分清四件事：预测、优化、推荐与控制

工艺智能项目最常见的概念混淆，是把质量预测、参数优化、参数推荐和过程控制都称为“智能调参”。四者相互连接，但任务边界并不相同。

### 1. 质量预测：给定参数，结果可能怎样

设产品、材料、设备和环境等上下文为 `c`，可控工艺参数为 `x`，产品质量、成本、节拍和能耗等结果为 `y`，质量预测模型学习的是：

```text
ŷ = f(c, x)
```

例如，注塑质量模型输入材料批次、模具、熔体温度、注射速度、保压压力和冷却时间，输出产品重量、翘曲量、关键尺寸和缺陷概率。

它回答的是：

> 如果这样生产，结果可能是什么？

预测模型是参数推荐的重要组成部分，但它不会天然告诉工程师应该选择哪组参数。

### 2. 参数优化：在目标和约束下寻找解

参数优化以预测模型、机理模型、仿真模型或真实试验为评价函数，在允许的参数空间中寻找更优解：

```text
x* = argmin L(f(c, x), target)
```

其中 `L` 可以同时包含尺寸偏差、缺陷风险、加工时间、成本和能耗。例如：

```text
总目标 = 0.5 × 质量损失
       + 0.2 × 周期时间
       + 0.2 × 能耗
       + 0.1 × 参数调整成本
```

如果存在多个相互冲突的目标，系统通常不会只得到一个答案，而会得到一组 Pareto 候选方案：有的质量更稳，有的效率更高，有的成本更低。

### 3. 参数推荐：结合上下文给出可执行建议

推荐系统需要在优化结果之外继续回答：

- 这组参数适用于哪种产品、材料、设备和环境？
- 是否超出历史数据覆盖范围？
- 是否满足设备能力、工艺规范和安全边界？
- 与当前参数相比，预计能改善多少？
- 推荐有多大把握，最坏情况是什么？
- 参考了哪些相似案例、规则、模型和试验？
- 如果首选方案不可用，还有哪些备选方案？

因此，推荐结果更接近一个结构化决策包：

```text
推荐参数值或参数区间
+ 预期质量、成本与节拍
+ 置信度和适用范围
+ 工艺约束检查结果
+ 相似历史案例
+ 推荐原因和敏感参数
+ 风险提示与备选方案
```

### 4. 过程控制：根据实时反馈持续调整

过程控制发生在生产运行期间。系统接收在线传感器、设备状态、过程量测或上一批次质量结果，再调整后续参数。

它回答的是：

> 现实状态已经发生变化，下一步应该怎样修正？

推荐系统可以停留在工程师审批的“建议模式”，也可以进一步进入 Run-to-Run 调节或实时闭环控制。但自动化等级越高，对数据时效、模型可信度、安全约束和回退机制的要求也越高。

四类任务之间的关系可以概括为：

```text
预测：参数 → 结果
优化：目标 → 候选参数
推荐：上下文 + 约束 + 候选参数 → 可执行决策
控制：实时反馈 + 决策策略 → 持续参数修正
```

把这四层分开，是设计工艺参数推荐系统的第一步。

## 二、参数推荐的本质，是一个上下文相关的约束决策问题

同一组参数很少对所有产品和所有设备都同样有效。参数是否合理，取决于它所处的制造上下文。

### 1. 推荐系统究竟需要理解哪些变量

一个完整的推荐任务至少包含五类变量。

| 类型 | 典型内容 | 是否可以直接调整 |
|---|---|---|
| 产品变量 | 型号、结构、尺寸、公差、关键特征 | 通常不能 |
| 材料变量 | 牌号、供应商、批次、含水率、成分 | 部分可选 |
| 资源变量 | 设备、腔体、模具、刀具、夹具 | 部分可选 |
| 状态变量 | 磨损、维护状态、环境温湿度、前序质量 | 通常不能直接调整 |
| 工艺参数 | 温度、压力、速度、流量、时间、功率 | 可以调整 |

系统输出的目标也不应只包含一个最终质量标签。它可能同时包括：

- 关键尺寸和几何精度；
- 表面质量和缺陷概率；
- 强度、硬度、密度等性能；
- 加工周期和设备利用率；
- 材料、能源和刀具成本；
- 碳排放和资源消耗；
- 参数改变对后续工序的影响。

### 2. 约束比“最优”更重要

工业参数空间不是一个可以任意搜索的数学空间。候选参数至少要经过四层约束：

**设备约束**：设备可达到的温度、压力、速度、功率和响应时间。

**工艺约束**：参数上下限、先后顺序、联动关系、升降速率和配方规则。

**质量约束**：关键指标必须满足规格，某些缺陷风险不能超过阈值。

**安全与治理约束**：禁止区域、审批要求、材料兼容性、模型适用范围和变更权限。

一个预测得分很高、但违反升温速率限制的方案不能被推荐；一个平均质量最好、但对材料波动极度敏感的方案也未必适合批量生产。

因此，推荐系统真正要寻找的不是一个孤立的最优点，而是一个**可行、稳健且可执行的工艺窗口**。

### 3. 参数点推荐与工艺窗口推荐

参数点推荐只输出一组数值：

```text
温度 230℃，压力 82 MPa，速度 47 mm/s
```

工艺窗口推荐则输出允许区间、耦合条件和敏感度：

```text
温度：228～233℃
压力：80～85 MPa
速度：45～49 mm/s

约束：当温度高于 232℃ 时，速度不得高于 47 mm/s
敏感项：压力每增加 1 MPa，关键尺寸预计增加 0.008 mm
```

对于真实生产，后者通常更有价值。设备存在控制误差，材料存在批次波动，环境和磨损状态也会变化。一个只有在极窄点位才能达到目标的方案，可能在实验室中最优，却不适合作为量产参数。

## 三、先建立可计算的“工艺案例”，再讨论算法

很多参数推荐项目并不是败在模型选择，而是败在数据无法还原一次真实生产。

### 1. 一条参数记录并不等于一个工艺案例

如果数据表中只有：

```text
温度、压力、速度、最终是否合格
```

模型很可能把大量上下文差异隐藏在误差中。它不知道样本来自哪种产品、哪台设备、哪套模具、哪个材料批次，也不知道加工时设备是否刚完成维护。

一个可用于推荐的工艺案例，至少应该描述：

```text
案例标识
├─ 产品：型号、版本、结构、关键特征、质量要求
├─ 材料：牌号、批次、供应商、来料属性
├─ 资源：工厂、产线、设备、腔体、模具、刀具
├─ 状态：环境、设备健康、磨损、维护、前序质量
├─ 配方：Recipe 及版本、参数设定值、参数实际值
├─ 过程：传感器 Trace、报警、暂停、人工干预
├─ 结果：量测、缺陷、性能、良率、节拍、成本
└─ 决策：调整原因、审批人、执行结果、适用结论
```

其中“设定值”和“实际值”必须区分。系统下发温度为 230℃，不代表整个加工过程中真实温度始终为 230℃。如果只保存 Recipe 而不保存过程 Trace，模型学习到的可能只是名义参数与质量之间的弱关系。

### 2. 数据必须按真实预测时点组织

推荐发生在首件生产前，就只能使用首件生产前已经知道的信息；推荐发生在上一批量测完成后，可以加入上一批质量和设备状态；在线控制则可以使用当前时刻的实时信号。

如果离线训练时加入了推荐时点之后才产生的数据，模型就会发生信息泄漏。它在测试集上表现很好，上线时却拿不到同样的信息。

因此，每个特征都应带有至少三项元数据：

- 它描述哪个对象；
- 它在什么时间产生；
- 在哪个决策时点可以使用。

### 3. 数据质量问题需要转化为业务语义

制造数据中的异常值不一定是错误。

- 突然升高的压力可能是设备故障，也可能是工程师有意试调；
- 缺失 Trace 可能是采集失败，也可能是设备没有执行该阶段；
- 同名参数在不同 Recipe 中可能具有不同物理含义；
- 参数单位可能在设备升级后发生变化；
- 合格标签可能来自不同版本的检验标准。

清洗数据时不能简单删除所有离群样本。更合理的做法是把异常分成：采集错误、业务例外、受控试验、设备异常和真实极端工况，再决定哪些数据可用于模型训练、风险建模或规则沉淀。

### 4. 从数据表走向工艺知识网络

传统宽表适合训练模型，却不擅长表达复杂关系。例如：

```text
产品 A 使用材料 M
材料 M 在设备 E 上适用 Recipe R3
R3 的参数 P1 受规则 C1 限制
缺陷 D 通常与参数 P1、P4 和模具状态 S 相关
案例 K 在相似条件下通过调整 P4 解决了缺陷 D
```

这些关系可以通过本体和知识图谱组织为产品、材料、设备、工序、参数、缺陷、规则和案例之间的语义网络。知识图谱不是为了替代时序数据仓库或机器学习特征表，而是为了补足三种能力：

- 查询某项经验适用于什么条件；
- 沿工艺关系找到相关规则和历史案例；
- 为推荐结果提供可追溯的解释证据。

## 四、六类技术路线，以及它们各自解决什么问题

工艺参数推荐没有一种算法可以覆盖所有场景。更现实的做法，是按数据条件、工艺风险和决策时效组合多种方法。

### 1. 规则与专家系统：先守住已知边界

规则系统把工艺规范和专家经验表示为条件与动作：

```text
IF 材料 = M1
AND 壁厚 < 1.2 mm
AND 设备 = E3
THEN 注射速度 ∈ [42, 50]
AND 熔体温度不得超过 235℃
```

它最适合表达：

- 设备硬限制和安全边界；
- 参数之间明确的联动关系；
- 工艺规范和审批规则；
- 已经反复验证的故障处置经验。

规则系统的优势是透明、稳定、容易审计，缺点是知识获取和维护成本高，也难以表示高维非线性关系。

即使企业计划使用深度学习或强化学习，规则层仍然不应被删除。算法负责在可行区域内寻找更优方案，规则负责明确哪些区域根本不能进入。

### 2. 案例推理：从相似产品复用成功经验

案例推理的基本思路是：新任务出现后，先寻找历史上最相似的产品和生产条件，再复用并修正成功方案。

典型过程包括：

```text
检索 Retrieve
  → 找到相似案例
复用 Reuse
  → 提取历史参数
修正 Revise
  → 根据差异调整
保留 Retain
  → 保存新结果
```

PCB 制造领域的研究曾将产品设计规格、工艺参数和生产质量保存为案例，通过相似案例识别关键参数并推断合理范围。这类方法特别适合多品种、小批量和新产品导入场景，因为它与工程师“先找相似产品”的工作方式一致。[1]

案例推理的关键不只是使用最近邻算法，而是设计合理的相似度：

- 哪些产品特征决定工艺相似性；
- 材料、设备和模具差异如何惩罚；
- 哪些质量结果说明案例确实成功；
- 历史案例距离当前时间越久，是否需要降低权重；
- 相似案例使用不同设备时，参数如何换算。

案例推理通常适合作为推荐系统的第一层基线：即使复杂模型不可用，系统仍能提供历史证据充分的候选方案。

### 3. 预测模型加优化算法：先学习结果，再反向搜索参数

这是当前最常见的数据驱动路线。针对生产过程优化的机器学习综述也表明，监督学习代理模型与搜索、优化算法的组合，已经成为连接历史生产数据与参数改进的重要技术范式。[11]

第一步，训练代理模型：

```text
产品 + 材料 + 设备状态 + 工艺参数
  → 质量、节拍、成本、能耗
```

第二步，让优化算法在代理模型上搜索参数。常用组合包括：

- 随机森林、XGBoost、支持向量回归或神经网络负责预测；
- 遗传算法、粒子群、差分进化、模拟退火或梯度方法负责寻优；
- NSGA-II 等多目标算法负责生成 Pareto 候选集。

这种方法把昂贵的真实试验替换为廉价的模型评价，可以探索更多候选方案。但它有一个重要前提：优化器可能主动寻找模型最不可靠的区域，因为那里有机会得到异常高的预测收益。

因此，优化时不能只计算预测均值，还要加入：

- 与训练数据分布的距离；
- 模型不确定性；
- 工艺规则违反惩罚；
- 参数变化幅度；
- 对扰动的敏感度；
- 多模型预测是否一致。

否则，系统得到的可能不是现实中的最优解，而只是“最能利用模型漏洞的输入”。

### 4. 贝叶斯优化：用尽可能少的试验寻找更优参数

当一次真实试验昂贵、耗时或有风险时，贝叶斯优化比大规模网格搜索更有吸引力。

它维护一个带不确定性的代理模型，并通过采集函数在两种行为之间权衡：

- **利用**：选择当前预测最好的区域；
- **探索**：选择不确定性高、但可能带来更好结果的区域。

每完成一次真实试验，系统就用新结果更新模型，再选择下一组参数。这使它适合新产品导入、工艺窗口开发和高成本实验设计。

在半导体光刻工艺研究中，基于高斯过程的贝叶斯优化被用于自动选择工艺参数，并在多个工艺实验中与人工选参进行比较。[2]

贝叶斯优化也并非天然安全。工业应用至少需要加入：

- 安全约束，禁止采样高风险区域；
- 批量采集策略，适配并行设备和试验批次；
- 混合变量处理，同时支持连续值、离散档位和类别变量；
- 多目标采集函数；
- 对材料批次、设备和环境变化的条件建模。

### 5. 知识图谱与上下文推荐：让参数方案带上适用条件

参数推荐最容易犯的错误，是只比较数值，不理解语境。知识图谱可以显式表达：

```text
产品特征 → 适用工序 → 可用设备 → 可选 Recipe
材料属性 → 参数限制 → 缺陷模式 → 调整策略
历史案例 → 执行条件 → 质量结果 → 验证结论
```

制造过程规划研究已使用知识图谱组织异构工艺知识，并通过元路径等方式支持检索和推荐；进一步的研究开始把任务上下文与图谱推荐结合，为工程师提供与当前设备和工艺任务更相关的知识。[3][4]

在参数推荐中，知识图谱可以承担四类职责：

1. 根据产品和资源上下文缩小候选 Recipe 与参数空间；
2. 检索相似案例、缺陷处置和工艺规则；
3. 为模型输入补充语义特征；
4. 生成“为什么推荐”的证据路径。

但图谱本身并不会自动产生准确参数。它更像连接规则、案例、文档、模型与决策的一层语义基础设施，数值计算仍需要统计模型、优化算法或机理模型完成。

### 6. 强化学习：把连续调参建模为序贯决策

传统优化通常把一次参数选择视为静态问题，强化学习则关注连续状态变化：

```text
状态 s：产品、当前质量、设备与环境状态
动作 a：参数值或参数调整量
奖励 r：质量改善 - 成本 - 时间 - 风险
策略 π：在状态 s 下选择动作 a
```

它适合多阶段装配、连续批次生产和需要根据反馈不断修正的场景。注塑研究已经尝试利用离线数据和质量预测模型训练强化学习决策策略，以动态调整过程参数；增材制造研究也探索了基于数字孪生环境的 Q-learning 参数优化。[5][6]

强化学习的最大障碍不是算法复杂度，而是探索风险。游戏智能体可以通过失败学习，真实设备和高价值产品却不能承受大量危险动作。

因此工业强化学习通常需要：

- 先在仿真或数字孪生环境中训练；
- 使用历史数据进行离线强化学习；
- 用规则和控制屏障限制动作空间；
- 从建议模式开始，由工程师审批；
- 保留稳定基线策略和一键回退能力；
- 对奖励函数进行严格审查，避免模型通过牺牲未建模指标换取高分。

## 五、机理模型和数字孪生，解决纯数据方法的边界问题

制造过程并不是任意的数据生成过程。热传导、材料流动、化学反应、力学变形和设备控制规律决定了参数如何影响结果。

### 1. 纯数据模型为什么容易失效

当历史数据丰富且生产条件稳定时，机器学习可以拟合复杂关系。但一旦出现以下情况，模型就可能迅速失去可靠性：

- 新材料或新产品超出训练分布；
- 设备维护后动态特性发生变化；
- 历史数据只覆盖狭窄的合格区域；
- 关键缺陷样本很少；
- 多个参数高度相关，模型难以分辨真实作用；
- 数据关系违反已知物理规律。

### 2. 数据与机理可以怎样融合

常见方式包括：

**机理模型生成数据**：通过仿真扩展真实试验难以覆盖的参数空间。

**数据模型修正机理残差**：机理模型描述主要规律，机器学习只学习未建模误差。

**物理约束进入损失函数**：训练时惩罚违反守恒关系、单调性或边界条件的预测。

**机理模型限定搜索空间**：先排除不可能或危险区域，再由数据模型优化。

**多保真联合建模**：少量高成本真实试验与大量低成本仿真共同训练代理模型。

2026 年的制造物理信息机器学习综述指出，将物理规律引入学习过程，主要希望改善纯数据方法的数据需求、物理一致性和可解释性问题；增材制造领域的相关综述则进一步从“工艺—组织—性能”映射角度总结了物理信息学习的应用方式。[7][12]

### 3. 数字孪生不只是一个三维界面

在参数推荐中，数字孪生真正有用的部分是：

- 同步设备和过程的当前状态；
- 在虚拟环境中评估候选参数；
- 根据现实数据校准模型；
- 将优化结果返回真实系统；
- 比较预测结果与实际结果并持续更新。

机器学习数字孪生已经被用于预测流程制造中的关键过程参数；更广义的研究也在探索机理模型与数据模型结合的动态预测和优化。[8][9]

但数字孪生不能自动消除模型误差。每个孪生模型都必须说明：

- 模型针对什么决策建立；
- 输入和边界条件是什么；
- 在哪些工况下经过验证；
- 预测误差和不确定性多大；
- 现实对象发生什么变化后需要重新校准。

## 六、一套可落地的工艺参数推荐系统架构

参数推荐系统可以分成七层。它们不一定对应七套独立软件，但职责需要清晰。

```text
制造系统与设备
  ↓
数据上下文层
  ↓
案例与知识层
  ↓
预测与机理模型层
  ↓
候选生成与优化层
  ↓
约束、风险与解释层
  ↓
推荐交互与执行层
  ↓
反馈评估与持续学习
```

### 1. 制造系统与设备层

连接 PLM、CAPP、MES、QMS、LIMS、SCADA、设备控制器、数据采集系统和工业物联网平台，获得产品定义、工艺路径、参数、Trace、量测和质量结果。

### 2. 数据上下文层

这一层负责把分散数据组织成统一制造对象：

- 哪个产品或批次；
- 在哪道工序；
- 使用哪台设备、腔体、模具和刀具；
- 使用哪个 Recipe 及版本；
- 参数设定值和实际值分别是什么；
- 生产前后设备和环境状态如何；
- 最终获得什么质量结果。

没有统一上下文，后面的推荐只能建立在模糊关联上。

### 3. 案例与知识层

保存并管理：

- 历史成功和失败案例；
- 参数范围和工艺规则；
- 缺陷模式与调整策略；
- 产品、材料、设备和工艺之间的语义关系；
- 试验结论及适用边界；
- 专家审批和人工修改记录。

### 4. 预测与机理模型层

这里不应只有一个“总模型”，而应形成模型组合：

- 关键质量预测模型；
- 缺陷风险模型；
- 周期、成本和能耗模型；
- 设备健康和漂移模型；
- 仿真或降阶机理模型；
- 不确定性与分布外检测模型。

不同模型可以按产品、工序和设备分别训练，也可以通过迁移学习和层次模型共享知识。

### 5. 候选生成与优化层

候选方案可以来自：

- 标准 Recipe；
- 相似案例；
- 工艺规则推导；
- 代理模型优化；
- 贝叶斯优化建议的下一次试验；
- 强化学习策略；
- 数字孪生仿真结果。

系统不必强迫所有方法给出同一个答案。更稳健的方式，是生成多个候选，再由统一评价层比较。

### 6. 约束、风险与解释层

这一层是“优化结果”转化为“推荐结果”的关键。

它需要检查：

- 硬约束是否全部满足；
- 候选是否超出模型适用范围；
- 预测置信区间是否可接受；
- 参数是否过于接近风险边界；
- 多个模型是否给出冲突结论；
- 参数对扰动是否稳健；
- 推荐依据是否足以支持当前自动化等级。

### 7. 推荐交互与执行层

工程师真正需要看到的，不是一个算法分数，而是可比较的方案：

| 内容 | 示例 |
|---|---|
| 推荐参数 | 温度 230℃，压力 82 MPa，速度 47 mm/s |
| 允许区间 | 温度 228～233℃ |
| 预计结果 | 尺寸偏差 0.012 mm，缺陷风险 3.8% |
| 相比当前 | 周期缩短 4.2%，能耗降低 2.1% |
| 置信度 | 中高；材料 M1、设备 E3 数据覆盖充分 |
| 主要依据 | 18 个相似案例、规则 R17、模型 V12 |
| 风险提示 | 模具使用次数接近模型训练上限 |
| 备选方案 | 稳健优先、效率优先各一组 |

任何人工修改都应记录修改人、原因和最终结果。工程师的修改不是“模型失败后的噪声”，而是未来改进规则、模型和界面的重要反馈。

## 七、推荐结果必须同时回答收益、不确定性与原因

### 1. 不确定性不是附加信息

两个候选方案的预测质量相同，但可信程度可能完全不同：

- 方案 A 附近有大量相似历史样本；
- 方案 B 位于训练数据边缘，只是模型给出了较高预测值。

如果系统只按预测均值排序，方案 B 可能被错误地排在前面。

推荐系统至少要识别三类不确定性：

**数据噪声**：即使参数相同，结果仍会因材料和环境波动而变化。

**模型不确定性**：训练数据不足，多个合理模型可能给出不同预测。

**分布外风险**：当前产品、设备或参数组合超出了历史覆盖范围。

不确定性可以转化为业务动作：

```text
高置信度 + 低风险 → 可进入受限自动执行
中等置信度 → 工程师审批后试产
低置信度 → 增加量测或设计试验
分布外样本 → 回退标准 Recipe，不自动推荐
```

### 2. 可解释不等于输出特征重要性

工程师真正需要的解释通常包括：

- 推荐与当前参数相比改变了什么；
- 哪些质量指标因此改善或恶化；
- 哪些参数最敏感；
- 参考了哪些相似成功案例；
- 哪条规则限制了候选范围；
- 哪些条件变化后推荐将不再适用。

SHAP 等特征归因方法可以解释预测模型依赖了哪些变量，但它不能单独证明改变某个参数一定会带来相同方向的质量变化。推荐系统应把统计归因、工艺机理、历史案例和试验结论组合起来，而不是把“模型认为重要”直接写成“工艺根因”。

### 3. 稳健性比峰值性能更重要

推荐方案应在小幅扰动下仍然满足要求。可以在候选参数周围进行蒙特卡洛采样或局部敏感性分析：

```text
x' = x + δ
```

其中 `δ` 表示设备控制误差、材料波动和环境变化。如果参数轻微变化就导致缺陷概率急剧上升，说明该方案位于脆弱边界，不适合稳定量产。

因此，候选排序可以加入鲁棒性指标：

```text
推荐得分
= 预期收益
- 质量波动风险
- 模型不确定性
- 参数调整成本
- 靠近约束边界的惩罚
```

## 八、怎样评价一个参数推荐系统是否真的有效

仅报告模型的 `R²`、准确率或 RMSE，无法证明推荐系统创造了制造价值。评价至少需要覆盖五个层次。

### 1. 预测层

- 回归误差：MAE、RMSE、`R²`；
- 分类性能：Precision、Recall、F1、PR-AUC；
- 概率校准：预测 10% 风险的样本是否真的约有 10% 失败；
- 分产品、设备、材料和时间段的稳定性。

### 2. 优化层

- 最优值改善幅度；
- Pareto 前沿质量；
- 收敛速度和真实试验次数；
- 约束违反率；
- 对参数扰动的稳健性。

### 3. 推荐层

- Top-K 候选中可被工程师接受的比例；
- 推荐采纳率和人工修改率；
- 首件成功率；
- 达到量产窗口所需的试调次数；
- 推荐覆盖率和低置信度回退率；
- 推荐解释是否能支持工程判断。

### 4. 制造结果层

- 合格率、良率和缺陷率；
- 关键质量指标的均值与波动；
- 工艺能力指数；
- 周期时间、能耗、材料和刀具成本；
- 报废、返工与停机损失。

### 5. 系统与治理层

- 推荐响应时间；
- 数据缺失时是否正确降级；
- 模型漂移检测时间；
- 审批、下发和回滚是否可追踪；
- 新模型上线后是否能与旧基线并行比较；
- 安全规则是否始终优先于模型输出。

### 6. 验证集不能随机拆分了事

如果同一批次、同一产品或相邻时间的样本同时进入训练集和测试集，模型分数容易被高估。更接近真实上线条件的验证方式包括：

- 按时间切分，使用未来批次测试；
- 留出新产品，验证冷启动能力；
- 留出设备，验证跨设备迁移；
- 留出材料批次，验证来料变化；
- 使用历史回放，模拟每个时点当时可见的数据；
- 进行影子运行，不下发参数，只比较建议与真实结果；
- 通过受控试验或 A/B 方案验证实际改善。

## 九、从离线模型走到生产闭环，需要分阶段提高自动化等级

工艺参数直接影响设备和产品，系统不应从概念验证一步跳到自动控制。

### 阶段一：数据回放

使用历史数据模拟推荐，检查系统能否在当时可见的信息条件下提出合理方案。此阶段重点验证数据关联、特征可用性和约束逻辑。

### 阶段二：影子模式

系统实时生成推荐，但不展示或不执行。等真实生产完成后，再比较推荐方案、工程师方案和实际结果。

### 阶段三：工程师建议模式

系统向工程师提供候选方案、依据和风险，由工程师决定是否采用。所有采纳、修改和拒绝原因都进入反馈数据。

### 阶段四：审批后执行

对于证据充分、风险较低的场景，工程师批准后由系统自动下发参数，同时保留版本、审批和回滚记录。

### 阶段五：受限自动闭环

系统只在经过验证的产品、设备、材料和参数窗口内自动调整；一旦出现分布外输入、异常状态或置信度下降，立即降级到人工模式。

### 阶段六：动态闭环优化

系统根据在线量测和生产结果持续更新策略。这一阶段需要成熟的模型治理、设备接口、安全约束、异常检测和组织责任体系。

自动化等级不是项目成熟度的唯一标准。对高风险、小批量或法规严格的工艺，长期保持“系统推荐、专家决策”可能比完全自动控制更合理。

## 十、以注塑成型为例，串起一次完整参数推荐

假设工厂要为一款高精度塑料零件推荐首件参数。

### 1. 定义任务

输入包括：

- 产品几何、壁厚和关键尺寸公差；
- 树脂牌号、批次和含水率；
- 注塑机、模具和模具使用次数；
- 车间温湿度；
- 当前设备维护与运行状态。

可控参数包括：

- 熔体温度；
- 模具温度；
- 注射速度；
- 保压压力和保压时间；
- 冷却时间。

目标包括：

- 关键尺寸偏差最小；
- 翘曲和缩痕风险低于阈值；
- 周期时间尽可能短；
- 参数不能超出设备与材料安全范围。

### 2. 生成初始候选

系统先查询标准 Recipe 和材料规则，确定硬边界；再检索相同材料、相似壁厚和相同模具类型的成功案例，得到三组历史参数。

### 3. 预测候选结果

质量模型分别预测尺寸、重量、翘曲和缺陷风险；周期模型预测加工时间；不确定性模型判断当前材料批次和模具状态是否处于历史覆盖范围。

### 4. 优化与稳健性检查

多目标优化算法在规则允许的范围内生成 Pareto 候选。系统在每组参数附近加入设备控制误差和材料波动，模拟候选方案的质量分布，淘汰对扰动过于敏感的方案。

### 5. 形成推荐

系统向工程师提供三组方案：

- 质量稳健优先；
- 周期效率优先；
- 质量与效率平衡。

每组方案都附带预计质量区间、相似案例、参数敏感度和风险提示。由于新材料批次的含水率略高于历史分布，系统把自动化等级降为“工程师审批后试产”。

### 6. 执行和反馈

工程师选择稳健方案，并根据经验将保压时间增加 0.4 秒。系统记录修改原因。首件完成后，真实尺寸和缺陷结果回写，模型比较预测误差；连续三个批次验证稳定后，这组案例被标记为“已验证”，并更新材料批次对应的工艺窗口。

这条链路说明，真正的推荐不是一次 `model.predict()`，而是数据、规则、案例、模型、优化、审批和反馈共同完成的一次受控决策。

## 十一、参数推荐项目最常见的失败方式

### 1. 只有参数和质量，没有制造上下文

模型把产品、设备、材料和环境差异混在一起，离线看似有效，换产品或换设备后迅速失效。

### 2. 把相关性当成可干预关系

模型发现某参数与高质量相关，不代表主动调整该参数就一定改善质量。该参数可能只是产品型号、设备选择或工程师策略的代理变量。

### 3. 只优化预测均值

系统忽略不确定性和分布外风险，优化器最终找到模型最自信却最缺少数据支持的区域。

### 4. 推荐一个精确点，却不说明允许波动

现场设备无法完美复现小数点后的参数。没有工艺窗口和敏感度，推荐方案难以稳定执行。

### 5. 只追求质量，不建模节拍、成本和设备影响

产品质量改善了，但周期显著增加，能耗升高或刀具寿命下降，整体收益反而为负。

### 6. 使用 Recipe 设定值代替真实过程值

系统忽略设备动态、超调、延迟和阶段波动，无法解释为什么相同 Recipe 得到不同结果。

### 7. 直接追求自动调参

数据关联、模型边界和规则体系尚未稳定，就让算法下发参数，会把分析误差放大为生产风险。

### 8. 只建设算法，不建设责任闭环

推荐由谁审核，参数由谁批准，失败后怎样回滚，模型漂移由谁处理，改善效果由谁确认，如果这些问题没有答案，系统很难长期运行。

## 十二、未来方向：从给出一个答案，走向可信的制造决策智能体

### 1. 从单工序推荐走向跨工序协同

最终质量往往由多道工序共同形成。前序参数造成的偏差可能被后序放大，也可能通过后序补偿。未来系统需要在工艺路径上联合分配参数，而不是让每道工序独立追求局部最优。

### 2. 从预测最优点走向因果和反事实决策

系统需要回答的不只是“哪些参数与质量相关”，还包括：

- 如果把参数从 A 调到 B，结果可能怎样变化；
- 这种变化对哪些产品和设备成立；
- 是否存在未控制的混杂因素；
- 哪种最小调整可以把当前状态带回合格区间。

### 3. 从固定模型走向持续学习

设备磨损、材料批次、产品组合和工艺规范会持续变化。推荐系统需要监测输入分布、预测误差、采纳率和实际改善，一旦模型失效就降级、重训或切换版本。

### 4. 从黑盒推荐走向证据组合

未来推荐结果可能同时引用：

- 相似历史案例；
- 工艺规则；
- 质量预测和不确定性；
- 机理仿真；
- 知识图谱路径；
- 受控试验结论。

不同证据彼此一致时，提高自动化等级；证据冲突时，主动请求工程师判断或追加试验。

### 5. 大模型成为交互和编排层，而不是数值真理来源

大模型可以读取工艺文档、检索案例、解释规则、调用预测模型和优化器，并把结果组织成工程师可读的建议。知识图谱与检索增强方法也正在被用于提高制造过程规划问答的准确性与可验证性。[10]

但大模型不应凭语言概率直接生成关键工艺数值并下发设备。可靠架构应让它负责理解意图、组织证据和编排工具，而让参数计算、约束检查和安全控制由经过验证的确定性组件完成。

一个面向未来的工艺参数决策智能体，更接近下面的结构：

```text
工程师提出目标
  ↓
智能体解析产品、工序和约束
  ↓
检索规则、案例和工艺知识
  ↓
调用预测、仿真和优化工具
  ↓
执行安全与适用范围检查
  ↓
生成多个带证据的推荐方案
  ↓
工程师审批或受限自动执行
  ↓
跟踪真实结果并更新知识
```

---

## 结语：参数推荐的终点不是算出最优值，而是建立可验证的决策闭环

工艺参数推荐看起来是在回答“参数设多少”，本质上却涉及制造企业如何组织数据、知识、模型、规则和责任。

一个成熟系统应当做到：

- 在正确的产品、材料、设备和环境上下文中理解参数；
- 区分设定值、实际过程和最终质量；
- 用规则守住硬边界，用案例复用历史经验；
- 用预测模型估计结果，用优化算法生成候选；
- 用机理和数字孪生补足纯数据模型的外推边界；
- 同时输出收益、不确定性、适用范围和推荐依据；
- 通过影子模式、人工审批和受限闭环逐步提高自动化等级；
- 用后续生产结果验证推荐，并把验证结论重新沉淀为组织能力。

因此，真正有价值的工艺参数推荐，不是给设备发送一组看起来精确的数字，而是建立下面这条长期运行的闭环：

```text
现实生产形成数据
数据与知识构成上下文
模型预测候选结果
约束与优化形成建议
工程验证并受控执行
真实结果校正模型和知识
```

当这条闭环建立起来，企业才能把少数专家脑中的调参经验，逐步转化为可复用、可验证、可治理并持续进化的制造决策能力。
