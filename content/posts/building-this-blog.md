这个博客使用 Next.js 构建，并通过 GitHub Actions 发布到 GitHub Pages。第一版没有后台、数据库和复杂的内容管理系统。

## 为什么选择静态网站

个人博客的核心需求很朴素：页面打开得快、文章容易长期保存、维护成本低。静态导出正好满足这些条件。

每次代码推送到 `main` 分支后，工作流会完成以下步骤：

1. 安装依赖；
2. 执行 Next.js 构建；
3. 导出静态页面；
4. 上传并部署到 GitHub Pages。

文章保存在 `content/posts` 目录中。每篇文章都是一个 Markdown 文件，文件顶部的元信息用于生成标题、摘要、日期和标签。

```md
---
title: 我的新文章
description: 文章的一句话介绍
date: 2026-09-07
tags: 学习, 项目
featured: false
---

从这里开始写正文。
```

## 简单意味着更容易持续

搭博客时很容易沉迷于主题、动画和功能，却迟迟没有真正发布内容。我希望第一版只保留支撑写作所需要的部分：

- 清晰的首页、文章列表和关于页面；
- 适合长时间阅读的排版；
- 深色模式和移动端适配；
- SEO 元数据、站点地图和语义化结构。

未来如果出现真实需求，再加入搜索、RSS、评论或项目页面。让功能追随内容，而不是让内容等待功能。
