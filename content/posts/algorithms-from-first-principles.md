学习算法时，最容易形成的一种错觉是：只要记住足够多的代码模板，就能解决足够多的问题。

模板当然有价值。它能减少重复书写，也能提醒我们一些容易遗漏的实现细节。但模板只能告诉我们代码通常长什么样，不能告诉我们为什么应该在这里使用它，更不能保证问题稍微变化后仍然有效。

真正稳定的理解，需要回答三个问题：

1. 最直接的做法浪费在哪里？
2. 更好的算法保存或利用了什么信息？
3. 算法运行过程中，始终成立的性质是什么？

哈希表是在保存已经见过的信息，前缀和是在保存已经算过的区间结果，动态规划是在保存已经解决的子问题。双指针依赖顺序带来的排除能力，二分依赖答案空间中的单调边界，贪心依赖局部选择不会破坏全局最优，图搜索则是在明确的状态空间中控制访问顺序。

从这个角度看，常见算法并不是一堆彼此孤立的技巧。它们都在做同一件事：

> **利用问题中的结构，避免不必要的计算。**

## 一、先理解问题，再选择算法

任何算法问题都可以先拆成四个部分：

- **数据**：输入由哪些对象组成，对象之间有什么关系？
- **操作**：允许读取、修改、选择或连接哪些内容？
- **目标**：要判断存在性、统计数量，还是寻找最优值？
- **约束**：数据规模、数值范围和结构限制是什么？

很多错误并不是因为不会某种算法，而是还没有说清楚自己到底在计算什么。

例如，“寻找一段满足条件的内容”仍然过于模糊。需要继续追问：

- 这段内容必须连续吗？
- 判断一段内容是否合法需要多少时间？
- 右端增加一个元素后，合法性如何变化？
- 左端删除一个元素后，能否快速更新状态？
- 是寻找最长、最短，还是统计总数？

这些问题的答案，会把一个模糊描述逐渐收敛为滑动窗口、前缀和、动态规划或其他更具体的模型。

### 从暴力解法开始

理解算法的最好起点通常不是最优解，而是暴力解法。

暴力解法能够暴露完整的候选空间，也能帮助我们定位真正的性能瓶颈。优化的过程，本质上是在回答：暴力过程中有哪些工作被重复做了？哪些候选可以提前排除？哪些结果可以被后续步骤复用？

以“数组中是否存在重复元素”为例，最直接的做法是比较所有元素对：

```python
def contains_duplicate_brute_force(nums: list[int]) -> bool:
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] == nums[j]:
                return True
    return False
```

它的问题不是双重循环本身，而是每遇到一个新元素，都重新扫描之前的元素。真正需要的信息只是：这个值以前是否出现过。

于是可以直接保存历史信息：

```python
def contains_duplicate(nums: list[int]) -> bool:
    seen: set[int] = set()

    for value in nums:
        if value in seen:
            return True
        seen.add(value)

    return False
```

哈希集合不是凭关键词想到的，而是从“反复查找历史数据”这个瓶颈中推导出来的。

## 二、复杂度是在约束下衡量增长速度

复杂度的作用不是给代码贴标签，而是判断一种思路能否随着数据增长继续工作。

| 复杂度 | 增长方式 | 常见来源 |
|---|---|---|
| `O(1)` | 与输入规模无关 | 直接访问、固定次数计算 |
| `O(log n)` | 每一步排除固定比例 | 二分、平衡树 |
| `O(n)` | 每个元素处理常数次 | 扫描、哈希、双指针 |
| `O(n log n)` | 分层处理，每层线性工作 | 排序、分治、堆操作 |
| `O(n²)` | 枚举元素对或二维状态 | 双重循环、二维动态规划 |
| `O(2^n)` | 枚举所有子集 | 状态压缩、选择型回溯 |
| `O(n!)` | 枚举所有排列 | 全排列回溯 |

复杂度只描述增长趋势，不代表所有同阶算法耗时完全相同。但它能快速排除数量级明显不合适的方向。

还要同时考虑空间复杂度。许多优化都在用空间换时间：哈希表保存历史信息，前缀和保存阶段结果，动态规划保存子问题答案，广度优先搜索保存待访问状态。

因此，判断一个方案时不能只问“快不快”，还要问“为了变快保存了多少信息”。

### 不要只数循环层数

两层循环不一定是 `O(n²)`。滑动窗口中，右指针和左指针都只向前移动，每个元素至多进入和离开窗口一次，总操作次数仍然是线性的。

同样，单调栈通常包含外层 `for` 和内层 `while`，但每个元素最多入栈一次、出栈一次，因此整体仍然是均摊 `O(n)`。

正确的分析方式是统计关键操作对每个元素最多发生多少次，而不是机械地数代码里出现了几层循环。

## 三、数据结构是操作能力的组合

数据结构不只是存放数据的容器。选择数据结构，实际上是在选择哪些操作必须足够快。

| 数据结构 | 主要能力 | 付出的代价 |
|---|---|---|
| 数组 | 按下标直接访问、连续遍历 | 中间插入和删除成本高 |
| 链表 | 已知位置后快速连接和断开 | 无法快速随机访问 |
| 哈希表 | 平均常数时间查找、插入和计数 | 额外空间，通常不维护顺序 |
| 栈 | 快速处理最近加入的元素 | 只能直接访问栈顶 |
| 队列 | 按加入顺序处理元素 | 不适合随机访问 |
| 堆 | 持续维护当前最小值或最大值 | 不保证所有元素整体有序 |
| 并查集 | 快速判断和合并连通关系 | 不适合表达一般路径信息 |

面对一个问题时，与其问“该使用哪种数据结构”，不如先问：

> 接下来的计算最频繁需要哪一种操作？

需要反复判断一个值是否出现过，就需要快速查找；需要不断取得当前最小值，就需要维护极值；需要按距离逐层扩展，就需要先进先出的处理顺序。

数据结构的选择，由操作需求决定。

## 四、哈希：把历史信息变成即时查询

哈希表适合处理“已经见过什么”以及“某种状态出现了多少次”。它通常把一次线性查找变成平均 `O(1)` 查询。

常见用途可以归纳为四类：存在性、计数、映射和分组。

例如，希望在数组中找到两个数，使它们的和等于 `target`。对当前值 `value` 来说，真正需要查询的是 `target - value` 是否已经出现：

```python
def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    positions: dict[int, int] = {}

    for index, value in enumerate(nums):
        required = target - value
        if required in positions:
            return positions[required], index
        positions[value] = index

    return None
```

这里先查询，再记录当前元素，可以避免在只允许使用一个元素一次时，把当前元素与自己配对。

设计哈希结构时，最重要的问题是确定键和值：键表示什么等价关系，值保存计数、位置、最优结果，还是完整对象？遇到相同键时，是覆盖、累加，还是保留第一次出现的位置？

例如，寻找最长区间时可能要保存某个状态最早出现的位置；统计区间数量时则需要保存状态出现的次数。虽然键可能相同，但值的语义不同，算法也会随之改变。

## 五、排序：通过重新排列暴露结构

排序的价值不只在于得到有序结果。更重要的是，有序性会让原本分散的关系变得局部化和可比较。

排序之后，相同元素会聚集在一起，区间可以按照起点或终点处理，双指针可以根据大小排除候选，贪心选择也可以按照某种优先级执行。

例如，合并重叠区间时，按左端点排序后，只需判断当前区间是否能与最后一个结果区间合并：

```python
def merge_intervals(intervals: list[list[int]]) -> list[list[int]]:
    if not intervals:
        return []

    intervals.sort(key=lambda item: item[0])
    merged = [intervals[0][:]]

    for start, end in intervals[1:]:
        last = merged[-1]
        if start <= last[1]:
            last[1] = max(last[1], end)
        else:
            merged.append([start, end])

    return merged
```

排序付出了 `O(n log n)` 的代价，但它把后续处理简化成一次线性扫描。判断是否应该排序时，可以问：排序后，相邻元素之间是否会出现原本难以观察的关系？

## 六、前缀和与差分：保存累计变化

如果同一段数据会被反复进行区间计算，逐次遍历区间就会产生大量重复工作。

### 前缀和保存“到这里为止的总量”

定义 `prefix[i]` 为前 `i` 个元素的和，那么闭区间 `[left, right]` 的和可以由两个前缀相减得到：

```text
sum(left, right) = prefix[right + 1] - prefix[left]
```

```python
def build_prefix_sum(nums: list[int]) -> list[int]:
    prefix = [0]
    for value in nums:
        prefix.append(prefix[-1] + value)
    return prefix


def range_sum(prefix: list[int], left: int, right: int) -> int:
    return prefix[right + 1] - prefix[left]
```

前缀和的核心不是公式，而是把“每次重新累计”改成“一次预处理，多次复用”。

前缀思想还可以保存计数、异或值或其他满足可组合性质的信息。能否使用前缀结构，取决于区间结果是否能由两个阶段状态快速组合或消去。

### 差分保存“从这里开始的变化”

如果需要多次给一段连续区间增加某个值，逐个修改区间中的每个位置会产生重复工作。差分数组只记录变化发生的边界：

```python
def apply_range_updates(
    length: int,
    updates: list[tuple[int, int, int]],
) -> list[int]:
    diff = [0] * (length + 1)

    for left, right, delta in updates:
        diff[left] += delta
        if right + 1 < length:
            diff[right + 1] -= delta

    result = [0] * length
    running = 0
    for index in range(length):
        running += diff[index]
        result[index] = running

    return result
```

前缀和把原数组转换为累计状态，差分则把原数组转换为变化状态。二者互为逆向过程。

## 七、双指针：用移动规则排除候选

双指针不是两个变量的固定写法，而是一种减少枚举范围的方法。它成立的关键是：移动某个指针后，被跳过的候选能够被证明不再需要考虑。

在有序数组中寻找和为 `target` 的一对数时：

- 当前和小于目标，右指针左移只会让和更小，因此应移动左指针；
- 当前和大于目标，左指针右移只会让和更大，因此应移动右指针。

```python
def find_pair(nums: list[int], target: int) -> tuple[int, int] | None:
    left = 0
    right = len(nums) - 1

    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return left, right
        if total < target:
            left += 1
        else:
            right -= 1

    return None
```

真正支撑代码的是有序性。没有这个条件，指针移动就失去了排除依据。

双指针常见的三种形态是相向指针、同向指针和快慢指针。无论采用哪一种形式，都需要给出一句明确证明：为什么移动这个指针不会错过答案？

## 八、滑动窗口：维护连续区间的不变量

滑动窗口可以看作同向双指针的一种特殊形式。右边界负责把新元素加入窗口，左边界负责在必要时移除旧元素。

一个滑动窗口通常需要定义三件事：

1. 窗口表示哪个区间；
2. 窗口内维护哪些统计信息；
3. 什么条件下必须收缩左边界。

以最长无重复子串为例，窗口不变量是：窗口内每个字符最多出现一次。

```python
def longest_unique_substring(text: str) -> int:
    counts: dict[str, int] = {}
    left = 0
    best = 0

    for right, char in enumerate(text):
        counts[char] = counts.get(char, 0) + 1

        while counts[char] > 1:
            removed = text[left]
            counts[removed] -= 1
            left += 1

        best = max(best, right - left + 1)

    return best
```

右边界每次加入一个字符。如果不变量被破坏，就不断移动左边界，直到窗口重新合法。只有在窗口合法时，当前长度才有资格更新答案。

滑动窗口通常需要满足三个条件：窗口状态可以增量更新；移动左边界能够让状态朝恢复合法的方向前进；左边界不需要回退。

如果区间中包含正负数，使得扩大区间后某个量可能增大也可能减小，简单滑动窗口往往失去单调性。这时可能需要前缀和、哈希或其他方法。

## 九、二分查找：寻找单调变化的边界

二分查找最重要的前提不是“数组已经排序”，而是搜索空间中存在单调性。

假设存在一个判断函数 `check(x)`，结果随 `x` 变化呈现如下结构：

```text
False False False True True True
```

二分查找要寻找的，就是第一个从 `False` 变成 `True` 的位置。

```python
def first_true(left: int, right: int, check) -> int:
    while left < right:
        middle = left + (right - left) // 2
        if check(middle):
            right = middle
        else:
            left = middle + 1
    return left
```

理解二分时，不要先背 `left`、`right` 如何加减，而要先确定四件事：搜索区间如何定义，答案为什么始终在区间内，判断成立时应该保留哪一半，循环结束后边界表示什么。

### 二分答案

当目标是寻找“最小可行值”或“最大可行值”时，也可以在答案范围上二分。

例如，某个容量越大，完成一组任务就越容易。若容量 `x` 可行，那么所有大于 `x` 的容量都可行，于是答案空间形成单调边界：

```text
不可行区域 | 最小可行答案 | 可行区域
```

这类方法的重点不在二分代码，而在于能否设计一个正确且足够快的 `check(x)`。

## 十、栈、队列与堆：让处理顺序服务于问题

这三种结构保存的都可以是“暂时还没有处理完的数据”，区别在于下一步取出谁。

### 栈：优先处理最近加入的元素

栈适合表达嵌套关系、撤销过程和最近未匹配对象。例如括号匹配中，右括号只能与最近一个尚未匹配的左括号配对。

单调栈则进一步维护栈内元素的单调性。当新元素到来时，弹出已经不可能成为后续答案的元素，从而在线性时间内寻找左右第一个更大或更小的位置。

### 队列：按照到达顺序推进

队列适合处理先到先得、逐层扩散和事件流。广度优先搜索使用队列，是因为先进入队列的状态通常距离起点更近。

### 堆：只维护当前最重要的元素

如果每一步只关心当前最小值或最大值，就没有必要让所有数据保持完全有序。堆只保证堆顶是极值，插入和删除堆顶通常为 `O(log n)`。

例如，从数据流中保留最大的 `k` 个元素，可以维护一个大小不超过 `k` 的最小堆：

```python
import heapq


def top_k_largest(nums: list[int], k: int) -> list[int]:
    heap: list[int] = []

    for value in nums:
        if len(heap) < k:
            heapq.heappush(heap, value)
        elif value > heap[0]:
            heapq.heapreplace(heap, value)

    return sorted(heap, reverse=True)
```

堆中保存的是当前最优的 `k` 个候选，堆顶则是这些候选中最容易被淘汰的那个。

## 十一、贪心：证明局部选择可以扩展为全局最优

贪心算法会在每一步做出当前看来最有利的选择，并且不回退。难点从来不是“选最大还是选最小”，而是证明这次选择不会破坏最终最优解。

常见的证明方式有两种。

### 交换论证

先假设存在一个最优方案。如果它没有采用贪心选择，尝试把其中某个选择替换为贪心选择，并证明替换后结果不会变差。这样就说明至少存在一个包含贪心选择的最优方案。

### 领先原则

证明贪心方案在每个阶段都不落后于其他方案。只要这种领先关系能持续到结束，贪心结果就是最优的。

以最多选择互不重叠区间为例，按照结束时间从小到大选择。优先选择最早结束的区间，会给后续区间留下不小于其他选择的可用空间。

```python
def max_non_overlapping(intervals: list[tuple[int, int]]) -> int:
    intervals.sort(key=lambda item: item[1])
    selected = 0
    last_end = float("-inf")

    for start, end in intervals:
        if start >= last_end:
            selected += 1
            last_end = end

    return selected
```

贪心失败的典型原因是：当前选择会影响未来选择，而且这种影响无法通过简单排序或交换消除。当局部选择之间存在复杂依赖时，通常需要搜索或动态规划保留多个可能状态。

## 十二、搜索：把所有可能性组织成状态空间

搜索并不等同于盲目枚举。一个完整的搜索模型需要定义：

- 状态包含哪些信息；
- 从当前状态可以执行哪些动作；
- 哪些状态已经访问过；
- 什么条件下得到结果；
- 什么条件下可以提前停止或剪枝。

### 深度优先搜索

深度优先搜索沿一条路径不断前进，无法继续时再返回。它适合遍历连通区域、分析树形结构，以及探索完整决策路径。

```python
def dfs(graph: list[list[int]], start: int) -> list[int]:
    visited = [False] * len(graph)
    order: list[int] = []

    def visit(node: int) -> None:
        visited[node] = True
        order.append(node)

        for neighbor in graph[node]:
            if not visited[neighbor]:
                visit(neighbor)

    visit(start)
    return order
```

访问标记非常重要。树天然没有回到祖先的边，而一般图可能存在环。如果不记录已访问节点，搜索可能无限重复。

### 广度优先搜索

广度优先搜索按层扩展。所有距离起点为 `d` 的状态都会先于距离为 `d + 1` 的状态被处理，因此它能够得到无权图中的最短步数。

```python
from collections import deque


def shortest_distances(graph: list[list[int]], start: int) -> list[int]:
    distance = [-1] * len(graph)
    distance[start] = 0
    queue = deque([start])

    while queue:
        node = queue.popleft()
        for neighbor in graph[node]:
            if distance[neighbor] == -1:
                distance[neighbor] = distance[node] + 1
                queue.append(neighbor)

    return distance
```

节点应在入队时标记，而不是出队时标记。否则同一节点可能被多个前驱重复加入队列。

### 回溯

回溯用于搜索由一系列选择构成的解。它通常包含三个动作：做出选择、进入下一层、撤销选择。

```python
def subsets(nums: list[int]) -> list[list[int]]:
    result: list[list[int]] = []
    path: list[int] = []

    def search(index: int) -> None:
        if index == len(nums):
            result.append(path[:])
            return

        search(index + 1)

        path.append(nums[index])
        search(index + 1)
        path.pop()

    search(0)
    return result
```

回溯的复杂度通常取决于状态空间本身。优化重点不是消灭所有指数增长，而是尽早识别不可能成功或不可能更优的分支。

## 十三、动态规划：给重复子问题建立记忆

动态规划适合同时具备两个特征的问题：大问题可以由规模更小的同类问题组成；不同决策路径会反复遇到相同子问题。

以斐波那契数列为例，直接递归会重复计算相同的 `fib(k)`。记忆化搜索把已经得到的结果保存起来：

```python
from functools import lru_cache


@lru_cache(maxsize=None)
def fibonacci(n: int) -> int:
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

自底向上的动态规划则按照依赖顺序主动计算状态：

```python
def fibonacci_iterative(n: int) -> int:
    if n <= 1:
        return n

    previous = 0
    current = 1

    for _ in range(2, n + 1):
        previous, current = current, previous + current

    return current
```

动态规划最重要的不是状态转移方程，而是状态定义。一个完整的设计过程通常包含五步：

1. **定义状态**：`dp[...]` 精确表示什么；
2. **列出选择**：当前状态可以通过哪些动作到达；
3. **建立转移**：当前答案依赖哪些更小状态；
4. **确定初始值**：最小规模的问题答案是什么；
5. **安排顺序**：计算当前状态前，它依赖的状态是否已经得到。

### 以 0-1 背包理解遍历顺序

每件物品只能选择一次。定义 `dp[capacity]` 为容量不超过 `capacity` 时能够取得的最大价值。

```python
def knapsack(weights: list[int], values: list[int], capacity: int) -> int:
    dp = [0] * (capacity + 1)

    for weight, value in zip(weights, values):
        for current in range(capacity, weight - 1, -1):
            dp[current] = max(
                dp[current],
                dp[current - weight] + value,
            )

    return dp[capacity]
```

容量必须从大到小遍历。这样读取的 `dp[current - weight]` 仍然来自处理当前物品之前的阶段，保证当前物品只使用一次。

如果从小到大遍历，刚刚更新的状态会再次参与后续转移，相当于允许同一物品被重复使用。遍历顺序并不是模板细节，而是由状态依赖关系决定的。

## 十四、图算法：研究对象之间的关系

当核心信息不再是单个对象的值，而是对象之间的连接、依赖或转换关系时，可以把问题建模为图。

图由节点和边组成：节点表示对象或状态，边表示连接、依赖、可达或转换，边权表示距离、成本、时间或其他代价。

| 目标 | 常见方法 | 关键条件 |
|---|---|---|
| 遍历连通区域 | DFS、BFS | 需要避免重复访问 |
| 无权最短路 | BFS | 每条边代价相同 |
| 非负权最短路 | Dijkstra | 边权不能为负 |
| 动态连通性 | 并查集 | 主要关心是否属于同一集合 |
| 依赖顺序 | 拓扑排序 | 图必须是有向无环图 |
| 最小连接成本 | 最小生成树 | 连接全部节点且总边权最小 |

### 并查集维护连通分量

并查集把每个连通分量表示成一棵树，通过根节点识别集合。

```python
class UnionFind:
    def __init__(self, size: int) -> None:
        self.parent = list(range(size))
        self.rank = [0] * size

    def find(self, node: int) -> int:
        if self.parent[node] != node:
            self.parent[node] = self.find(self.parent[node])
        return self.parent[node]

    def union(self, first: int, second: int) -> bool:
        root_a = self.find(first)
        root_b = self.find(second)

        if root_a == root_b:
            return False

        if self.rank[root_a] < self.rank[root_b]:
            root_a, root_b = root_b, root_a

        self.parent[root_b] = root_a
        if self.rank[root_a] == self.rank[root_b]:
            self.rank[root_a] += 1

        return True
```

路径压缩会让查找过程中经过的节点直接连接到根；按秩合并则避免树退化得过高。并查集非常擅长回答“是否连通”，但无法直接给出两点之间的具体路径。

## 十五、状态压缩：用整数表示集合

当元素数量较少，而计算需要区分大量“选了哪些元素”的状态时，可以用二进制位表示集合。

假设有 `n` 个元素，一个整数的第 `i` 位表示第 `i` 个元素是否被选中。常见操作包括：

```python
selected = (mask & (1 << index)) != 0
with_item = mask | (1 << index)
without_item = mask & ~(1 << index)
toggled = mask ^ (1 << index)
```

状态压缩没有降低状态数量，`n` 个元素仍然有 `2^n` 个子集。它的价值是让集合状态更紧凑，并让判断、添加和删除元素都能通过位运算完成。

因此，看到较小的元素数量时，可以考虑：真正需要记录的是否不是顺序，而只是一个子集？

## 十六、不变量：证明算法在每一步都没有走偏

很多算法代码很短，正确性却不直观。不变量是连接直觉和证明的桥梁。

不变量是在循环或递归的每个关键阶段都成立的性质。例如：

- 二分查找中，答案始终位于当前搜索区间；
- 滑动窗口更新答案时，窗口始终满足约束；
- Dijkstra 取出未确定节点中的最小距离时，该距离已经无法再被改小；
- 归并排序合并过程中，结果区间始终保持有序；
- 0-1 背包处理完前 `i` 件物品后，状态只使用这 `i` 件物品。

验证一个不变量，可以分成三步：

1. **初始化**：循环开始前是否成立；
2. **保持**：执行一次迭代后是否仍然成立；
3. **终止**：循环结束时，不变量是否能推出最终结论。

当一段算法难以解释时，可以尝试补全这句话：

> 每次进入循环时，我可以确定 ______ 始终成立。

如果无法填出明确内容，通常意味着状态定义、边界条件或移动规则还不够清楚。

## 十七、把常见算法放回同一张地图

常见算法可以按照“它消除了哪一种浪费”来理解：

| 观察到的浪费或结构 | 对应思想 |
|---|---|
| 反复查找历史元素 | 哈希 |
| 反复计算相同区间 | 前缀和 |
| 反复修改连续区间 | 差分 |
| 有序性可以排除候选 | 双指针 |
| 连续区间可以增量维护 | 滑动窗口 |
| 判断结果随参数单调变化 | 二分 |
| 只需要持续取得极值 | 堆 |
| 最近加入的对象先完成 | 栈 |
| 状态需要按距离逐层扩展 | BFS |
| 需要完整探索选择路径 | DFS、回溯 |
| 相同子问题被多次计算 | 动态规划 |
| 局部选择可证明不影响最优性 | 贪心 |
| 核心信息是对象之间的连接 | 图算法 |
| 核心状态是一个较小集合 | 状态压缩 |

这张表不是关键词匹配表。它更像一组诊断问题，帮助我们识别计算过程中的瓶颈。

## 十八、一套可重复使用的推导流程

面对一个新的算法问题，可以按照下面的顺序思考。

### 第一步：明确状态与目标

用一句不含背景描述的话重新表达问题。例如，在数组中寻找满足约束的最长连续区间，或者在带权图中寻找从起点到终点的最小代价。

### 第二步：写出最直接的做法

即使暴力解法很慢，也要说清楚它枚举了什么。只有知道完整候选空间，才能判断优化有没有遗漏答案。

### 第三步：计算复杂度

明确最耗时的操作，以及它最多执行多少次。判断当前复杂度是否与数据规模匹配。

### 第四步：寻找重复工作

检查是否在重复查找、重复求和、重复排序、重复访问状态或重复解决相同子问题。

### 第五步：寻找结构性质

数据是否有序？判断函数是否单调？答案是否由更小状态组成？局部选择是否可以交换？对象之间是否形成图？

### 第六步：定义不变量

明确算法运行过程中始终保持什么性质。指针为什么这样移动，状态为什么这样转移，访问顺序为什么正确，都应该能够由不变量解释。

### 第七步：验证边界

至少检查空数据、单个元素、全部相同、严格递增、严格递减、重复值、极端数值、无解和多解等情况。

### 第八步：重新分析复杂度

优化之后再次统计时间和空间成本，确认没有把高复杂度操作隐藏在辅助函数、切片、复制或容器操作中。

## 十九、如何判断自己是否真正理解

能写出代码并不等于理解算法。可以通过以下问题进行检验：

1. 能否先写出正确的暴力方案？
2. 能否指出暴力方案具体重复了什么？
3. 能否不用算法名称解释优化思路？
4. 能否说清楚每个状态、指针或容器中保存的内容？
5. 能否给出算法成立所依赖的不变量？
6. 能否构造一个让相似方法失效的反例？
7. 改变一个条件后，能否判断原方法是否仍然成立？
8. 能否从零重新推导，而不是回忆代码形状？

例如，真正理解滑动窗口，不只是会写左右指针，而是知道它为什么要求连续区间、为什么左边界只前进不后退，以及哪些数据性质会让这种单向移动失效。

真正理解动态规划，也不是记住若干转移方程，而是能够识别重复子问题，定义足以描述未来决策的状态，并按照依赖关系安排计算顺序。

## 二十、结语：算法是对计算过程的重新组织

算法学习最值得保留的，不是越来越长的模板列表，而是一套越来越稳定的推导能力。

看到反复查找，就考虑保存历史；看到重复区间计算，就考虑预处理；看到有序和单调，就考虑排除一半或移动边界；看到重复子问题，就考虑记录状态；看到对象之间的连接，就考虑图；看到大量选择，就分析状态空间以及是否能够剪枝。

最终，算法不再表现为“这一类问题要背哪段代码”，而会变成几个更本质的问题：

- 哪些工作没有必要重复？
- 哪些信息值得保存？
- 哪些候选可以被证明不可能？
- 哪个状态足以描述已经完成的部分？
- 哪个性质能够保证每一步都朝正确方向前进？

能够持续回答这些问题，就能够从问题本身推导算法。代码模板仍然可以使用，但它只是理解之后的简写，不再是理解的替代品。
