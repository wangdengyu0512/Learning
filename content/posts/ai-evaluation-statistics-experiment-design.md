旧版采购 Agent 的成功率是 82%，新版是 86%。团队准备上线，因为看起来提升了 4%。

这里至少有五个问题尚未回答：用了多少任务，是否是同一批任务，任务是否代表真实流量，成功是如何判定的，以及这次提升会不会只是抽样波动。

**一个评测分数只有放进抽样方式、比较设计和不确定性之中，才足以支持决策。** 本文使用人工构造的数据演算统计方法，不代表任何真实模型成绩。文中的代码可以复算示例，但不替代完整实验设计。

## 一、先明确要估计的量

“Agent 更好”可能指一次尝试成功率、最终任务完成率、人工接管减少，或单位成本下完成更多任务。这些量不能互相替代。

对于采购任务，可以预先规定：

| 项目 | 示例定义 |
| --- | --- |
| 评估总体 | 本季度允许自动处理的标准采购需求 |
| 实验单位 | 一条独立采购需求 |
| 主指标 | 在时间预算内、无需人工修复完成正确订单的比例 |
| 成功判定 | 对象正确、数量金额正确、审批有效且无重复副作用 |
| 护栏指标 | 越权事件、重复订单、超时率、人工接管和成本 |
| 实际改善门槛 | 由业务预先确定值得投入的绝对提升幅度 |

如果新版通过无限重试获得更高完成率，成本和延迟可能同时恶化。因此，应固定预算或把预算变化作为实验因素，并保留失败与超时样本。

人工接管可以是产品成功路径，但若主指标定义为“无需人工修复”，就不能把接管后的成功混入自动成功率。可以另外报告整体完成率。

## 二、样本量之外，还要关心样本从哪里来

抽取 1000 条简单任务，未必比覆盖关键边界的 200 条任务更适合回答上线问题。代表性和精度是两个不同维度。

可以按业务类型、金额区间、工具数量和异常类型分层抽样。若困难任务被刻意多采样，计算整体生产效果时需要按目标业务分布加权，同时保留各分层结果。

同一客户的相似需求、同一文档派生的问题或同一模板的多次改写，可能高度相关。把它们都当成独立样本，会低估不确定性。

训练、开发和验收集合也需要隔离。根据某一批失败样例反复修改提示词后，这批样例适合做回归检查，却不再是完全独立的最终验收证据。时间敏感业务还应考虑按时间切分，避免未来信息进入输入。

## 三、82% 到 86% 首先是 4 个百分点

绝对提升为：

```text
86% - 82% = 4 个百分点
```

相对成功率提升约为：

```text
(86% - 82%) / 82% ≈ 4.88%
```

如果关注失败率，则从 18% 降到 14%，相对下降约 22.22%。三种说法可以同时成立，但表达的是不同量。

报告时优先写出原始分子、分母和绝对变化，再补充相对变化。这样可以避免用听起来更大的百分比掩盖有限的业务效果。

## 四、对单个成功率给出区间

若 100 个独立、同分布的二元任务中成功 86 个，样本成功率为 0.86。它是对目标成功概率的估计，不是精确常数。

在二项模型下，可以用 Wilson 区间表达不确定性。其计算比简单的正态近似更适合一些小样本或接近边界的比例情况。[1]

下面代码使用 Python 标准库计算常用 95% 区间。`z` 采用标准正态分布的近似分位数。

```python
from math import sqrt


def wilson_interval(successes, total, z=1.959963984540054):
    if total <= 0 or not 0 <= successes <= total:
        raise ValueError("invalid counts")
    p = successes / total
    denominator = 1 + z * z / total
    center = (p + z * z / (2 * total)) / denominator
    radius = z * sqrt(
        p * (1 - p) / total + z * z / (4 * total * total)
    ) / denominator
    return center - radius, center + radius


for successes in (82, 86):
    low, high = wilson_interval(successes, 100)
    print(successes, f"[{low:.4f}, {high:.4f}]")
```

在这些假设下，82/100 的区间约为 73.33%～88.30%，86/100 约为 77.86%～91.47%。这里可以看到估计有明显不确定性。

频率学派的 95% 置信区间指构造方法在重复抽样下的覆盖率，不能直接解释为“当前固定参数有 95% 概率落在这段区间内”。[1]

也不能根据两段区间是否重叠，直接完成两个方案的差异检验。比较设计和样本相关性需要进入差异分析。

## 五、同一批任务应保留配对关系

假设两个方案都运行同样的 100 个任务，得到下表：

| 结果组合 | 任务数 |
| --- | --- |
| A、B 都成功 | 78 |
| A 成功、B 失败 | 4 |
| A 失败、B 成功 | 8 |
| A、B 都失败 | 10 |

A 成功 82 次，B 成功 86 次。配对改善仍是 4 个百分点，但能够直接区分两个方案的任务只有 12 个：B 新增解决 8 个，同时退化 4 个。

对于独立任务对的二元结果，可以对不一致的配对进行精确二项检验，这对应精确 McNemar 检验的常见实现。零假设下，两种不一致方向的概率相同。[2]

以下代码针对这一个教学例子，计算其双侧概率：

```python
from math import comb

regressions = 4
improvements = 8
discordant = regressions + improvements

p_value = min(
    1.0,
    2 * sum(comb(discordant, k) for k in range(min(regressions, improvements) + 1))
    / (2 ** discordant),
)
print(f"{p_value:.6f}")
```

结果约为 0.387695。在预先设定的 0.05 阈值下，这组数据不足以拒绝对称的零假设。它不证明两个方案相同，也不证明新版没有价值；它说明现有证据不足以支持一个强差异结论。

该简短公式利用了零假设概率为 0.5 的对称性，不能直接推广到任意二项检验。实际分析可以使用经过验证的统计库，并检查检验前提。

## 六、同时估计差异大小，而不只看 p 值

上线决策关心改善有多大、可能落在哪个范围，以及是否值得承担风险。p 值不能替代效应量和业务判断。

对于配对任务，可以构造每个任务的差值 `d = B - A`，取值为 -1、0 或 1。整体差异是这些差值的平均值。

一种区间估计方法是对任务对进行 bootstrap：每次抽样保留同一任务的 A、B 结果，再重新计算均值差。若任务按客户或文档聚集，应在合适的簇层级重采样；分层设计也应保留相应权重。[3]

不要独立打乱 A 和 B 的样本，那会丢掉配对信息。对于小样本、稀少失败或极端比例，区间方法也可能不稳定，需要检查方法适用性并报告限制。

业务上还可以预先设定最低值得采用的改善幅度。如果变化很小但统计上显著，仍可能不值得承担迁移成本；相反，置信范围很宽的高风险变化，可能需要更多数据。

## 七、多次运行与多任务样本承担不同作用

同一个 Agent 在同一任务上重复运行，可以观察随机性。但运行 100 次同一采购任务，并不等于观察了 100 种独立业务情境。

可以把实验设计成两层：先抽取代表性任务，再为每个任务固定次数运行。分析时以任务为主要单位，保留任务内波动，必要时使用分层模型或簇级重采样。

还要固定成功率的分母含义。“一次尝试成功率”和“最多五次尝试内至少一次成功率”是不同指标。后者会改变费用、时延和实际产品行为。

如果线上不会挑选最好的一次输出，离线就不应只保留多次生成中的最佳结果。温度设为零也不能作为所有环境都完全可重复的保证，仍应记录模型、配置和运行条件。

## 八、离线配对评测与线上随机实验各自回答什么

离线评测让两个方案面对同样输入，便于定位能力差异。线上实验则观察真实使用行为和业务结果，但涉及分组、时间趋势与相互影响。

采购场景可能存在供应商、预算和库存共享。若按每次点击随机分组，同一需求可能先后接触两个方案，处理结果也可能影响另一组。实验单位可以考虑需求、团队或其他稳定边界，但单位改变会影响样本量和分析方法。

随机化用于降低系统性差异，不能保证每次小样本都完全平衡。应预先检查关键基线，并使用与分配方式一致的分析。

无法随机化时，可以采用前后对照、匹配或准实验方法，但要明确假设。同期业务变化、人员调整和任务难度变化，都可能解释观测到的提升。已有[研发效能实验文章](../developer-productivity-flow-efficiency-experimentation/)可以继续展开这些方法。

## 九、避免在实验过程中不断改变判定方式

反复查看结果，看到一次显著就停止，会改变普通固定样本检验的错误率。应预先固定实验长度、采用适当的序贯方法，或把探索结果与确认实验分开。

同时尝试很多提示词、很多模型，再只报告最高分，也会产生选择偏差。开发阶段可以广泛探索，最终验收应使用保留集或独立时间窗口。

样本量规划需要基线成功率、最低关注差异、显著性水平、检验功效和实验设计。配对实验还依赖不一致结果的比例，不能套用一个通用的“至少 100 条”。

## 十、评判器本身也是测量系统

当“成功”由另一个模型判断时，评测可能受到评判器偏好、顺序效应和版本变化影响。

采购任务中的硬条件应优先通过外部事实检查，例如订单编号、数量和重复订单数。需要判断解释质量的部分，可以采用盲评、顺序随机化、多人复核和争议仲裁。

抽取人工标注样本，检查评判器在不同失败类型上的一致性。只看总体一致率，可能掩盖它对少数高影响错误的漏判。

评判规则、工具模拟器和环境也需要版本化。否则分数变化可能来自评分标准改变，而不是 Agent 能力变化。

## 十一、最小实践：制作一份能支持决策的评测记录

准备一组带独立任务标识的采购样例，保存以下字段：

```text
task_id, task_group, scenario, dataset_version,
variant, run_id, model_version, prompt_version,
success, failure_type, elapsed_ms, cost,
judge_version, evidence_reference
```

先检查任务是否完整配对，是否遗漏超时和失败；再输出整体和关键分层的成功率、差异、区间及护栏结果。保留不一致任务清单，逐条查看新版改善了什么、退化了什么。

对于本文 100 对教学样本，一份合理结论应明确：观察到 4 个百分点改善；其中 8 个任务改善、4 个退化；精确配对检验没有提供强差异证据；后续需要根据实际门槛和失败类型决定补样或修复。

样本没有出现越权或重复订单，也不能证明风险为零。对于罕见高影响故障，应增加定向场景测试，并用适合稀有事件的统计口径报告上界。

## 十二、让结论与证据保持同样大小

一份完整报告应写出目标总体、抽样方式、任务数、重复次数、主指标、效应量、不确定性、护栏和局限。

证据只能支持标准采购任务，就不要直接扩展到复杂跨国采购。结果只来自模拟工具，也不能推断真实 ERP 的执行可靠性。统计方法帮助我们明确还能推断到哪里，以及哪些问题需要下一次实验回答。
