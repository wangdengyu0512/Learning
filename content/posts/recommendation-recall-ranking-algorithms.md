推荐系统通常被描述成一个“预测用户喜欢什么”的模型，但真正上线时，它首先要解决的是规模问题：面对数百万甚至数亿个候选，系统不能为每个用户逐个运行最复杂的模型。因此，一个成熟的推荐链路通常会把问题拆成召回、粗排、精排和重排几个阶段。

召回负责从全量物品中快速找出一批可能相关的候选；粗排使用较轻的模型进一步缩小集合；精排综合用户、物品、上下文和行为序列，预测点击、观看、购买或停留等目标；重排则在列表层面处理多样性、去重、业务约束和流量策略。

```text
全量物品 → 多路召回 → 粗排 → 精排 → 重排 → 最终列表
  百万级      千到万级    百到千级   几十到百级    展示位
```

这条链路也解释了为什么 CF、双塔和 DeepFM 经常一起出现：它们解决的问题不同。协同过滤擅长从行为关系中找相似性，双塔擅长把大规模匹配转化为向量检索，DeepFM 擅长在候选已经较少时学习稀疏特征之间的交互。

## 一、先区分召回与排序

召回阶段最重要的指标是覆盖率、相关候选命中率和检索延迟。一个候选如果没有被召回，后面的排序模型再强也无法把它展示给用户。因此，召回通常允许一定的误召回，只要能够尽可能保留真正有价值的候选。

排序阶段的候选数量已经明显减少，模型可以使用更丰富的特征。例如，排序模型可以同时使用用户画像、物品属性、当前页面、设备、时间、历史行为以及用户与当前物品的交互特征。它的重点从“这个物品有没有可能相关”变成“这一批候选中，哪个更应该排在前面”。

线上系统往往会并行运行多个召回通道：

- ItemCF 召回用户历史物品的相似物品；
- 双塔召回与当前用户向量最接近的物品；
- 热门和趋势召回保证冷启动及整体供给；
- 内容召回利用标签、文本、图像或音频相似性；
- 规则召回满足运营、地域、库存或业务活动要求。

多路召回结果合并后，通常还要去重、过滤已消费物品，再交给排序模型处理。召回通道的组合本身也是推荐系统效果的重要来源。

## 二、协同过滤：从用户行为中寻找关系

协同过滤（Collaborative Filtering，CF）的基本假设是：有相似行为的人可能有相似兴趣，和某个物品存在稳定关联的物品也可能适合被一起推荐。它不要求系统理解内容的语义，而是直接利用用户与物品之间的交互记录。

### 1. UserCF 与 ItemCF

UserCF 先计算用户之间的相似度，再把相似用户喜欢的物品推荐给当前用户。ItemCF 则计算物品之间的相似度，根据用户已经交互过的物品寻找邻居。Sarwar 等人在 2001 年发表的《Item-Based Collaborative Filtering Recommendation Algorithms》系统讨论了 ItemCF 的相似度计算和预测方法。

对于二值行为，可以用共同用户集合计算一种简单的余弦相似度：

\[
\operatorname{sim}(i,j)=
\frac{|U_i\cap U_j|}{\sqrt{|U_i|\cdot|U_j|}}
\]

其中，\(U_i\) 是与物品 \(i\) 发生过交互的用户集合。对用户历史中的每个物品，系统取它的相似物品并加权汇总，就能生成候选。

ItemCF 的在线计算相对简单，物品相似度也可以提前离线计算。它还具有一定的可解释性：系统可以说明“因为你看过 A，所以推荐与 A 相似的 B”。但它也依赖足够的交互数据。新物品没有历史行为时，很难获得可靠的协同邻居；行为稀疏时，相似度也容易不稳定。

### 2. CF 的工程问题

实际系统中的行为并不等价。一次曝光、点击、短暂停留、完整观看、收藏和购买，通常应当拥有不同的权重。还要考虑时间衰减：用户一年前看过的内容，可能不如刚刚看过的内容有参考价值。

因此，一个简单的 ItemCF 分数往往会扩展成：

\[
score(u,j)=\sum_{i\in H(u)}w(u,i)\cdot sim(i,j)
\]

其中，\(H(u)\) 是用户历史，\(w(u,i)\) 可以同时包含行为类型权重、时间衰减、场景权重和业务过滤结果。

CF 很适合作为第一条召回通道和强基线。它实现成本低、解释性好、延迟可控，也能提供稳定的相似内容候选。但当特征类型变多、用户兴趣变复杂、物品规模持续扩大时，仅靠邻居关系就不够了。

## 三、矩阵分解：把用户和物品放进同一个向量空间

矩阵分解把用户与物品的交互矩阵近似为两个低维矩阵。每个用户拥有一个向量 \(p_u\)，每个物品拥有一个向量 \(q_i\)，偏好分数由内积给出：

\[
score(u,i)=p_u^\top q_i
\]

对于显式评分，可以加入全局偏置、用户偏置和物品偏置：

\[
\hat r_{ui}=\mu+b_u+b_i+p_u^\top q_i
\]

Koren、Bell 和 Volinsky 在 2009 年的《Matrix Factorization Techniques for Recommender Systems》中系统介绍了矩阵分解在推荐系统中的应用，并讨论了隐式反馈、偏置和时间因素等扩展。

矩阵分解相当于把“用户喜欢什么”和“物品具有什么特征”压缩到一个共同的潜在空间。向量的每个维度通常不直接对应一个人工命名的主题，但用户向量和物品向量的方向关系可以表达协同偏好。

如果输入只有用户 ID 和物品 ID，矩阵分解对新用户、新物品仍然存在冷启动问题。加入物品内容、用户属性或预训练表示，可以缓解这个问题，但也会让模型从简单的 ID 协同过滤逐渐走向特征化模型。

### 训练目标比模型名字更重要

推荐系统中的“未点击”不一定代表“不喜欢”。用户可能没有看到它，也可能被其他内容挡住。因此，隐式反馈训练通常要构造正负样本或相对偏好。

BPR（Bayesian Personalized Ranking）提出了面向个性化排序的成对训练目标。对于用户 \(u\)、已交互物品 \(i\) 和采样的未交互物品 \(j\)，模型希望满足：

\[
score(u,i)>score(u,j)
\]

其核心损失可以写为：

\[
-\log \sigma(score(u,i)-score(u,j))
\]

这类目标直接优化相对顺序，适合“把用户喜欢的物品排在前面”的任务。实际训练时，负样本的分布、采样频率和难度都会影响最终效果。

## 四、双塔模型：把大规模匹配转成向量检索

双塔模型把用户侧和物品侧分别编码成向量：

\[
z_u=f_\theta(x_u),\qquad z_i=g_\phi(x_i)
\]

再用内积或余弦相似度计算匹配分数：

\[
score(u,i)=z_u^\top z_i
\]

用户塔可以接收用户 ID、画像、历史行为和上下文；物品塔可以接收物品 ID、类别、文本、图像或其他内容特征。相比只学习 ID 向量的矩阵分解，双塔可以使用更丰富的编码器。

双塔适合召回的关键原因是物品向量可以提前计算。离线生成所有物品向量后，系统可以建立近似最近邻索引。在线请求只需要计算一次用户向量，再从索引中搜索相近物品，避免对全量物品逐个执行复杂的联合模型。

Google 的《Deep Neural Networks for YouTube Recommendations》介绍了大规模推荐系统中的候选生成与排序分工。之后的《Sampling-Bias-Corrected Neural Modeling for Large Corpus Item Recommendations》进一步讨论了大规模物品推荐中的采样偏差和双塔训练问题。

从结构上看，矩阵分解可以看作双塔的一个特例：两侧只查找 ID Embedding，最后进行内积。如果两侧加入多种特征和神经网络，就得到更一般的双塔架构。

### 双塔的边界

双塔为了支持独立编码，通常把用户与物品的复杂交互推迟到最后的向量匹配。它不能在物品塔中直接使用当前用户的实时特征，也不适合建模非常细致的候选相关历史兴趣。

例如，用户同时喜欢摄影和旅行。当候选是摄影教程时，系统应该重点关注用户的摄影行为；当候选是旅行攻略时，应该重点关注旅行行为。如果用户塔只生成一个固定向量，可能无法充分表达这种候选依赖关系。

因此，双塔通常负责“从全库找到可能相关的内容”，而候选相关的精细判断交给后续排序模型。

### 负采样与批内负样本

双塔训练无法每次都把全量物品作为负样本，工程上常用随机负采样、热门负采样、曝光未点击采样和批内负采样。

批内负采样会把同一批次中其他样本的正物品作为当前样本的负候选，计算效率很高。但物品流行度通常是不均匀的，热门物品更容易出现在批次中，训练分布会因此偏离真实分布。采样偏差修正论文正是针对这类问题进行研究。

负样本策略还会影响模型学到的能力：随机负样本更容易，难负样本更接近真实竞争候选，但也可能引入误标样本。一个实用方案是从多种来源混合采样，并分别监控召回覆盖、热门度偏差和长尾物品表现。

## 五、FM：为稀疏特征学习二阶交互

在排序阶段，输入往往是大量离散特征：用户 ID、物品 ID、类别、设备、地域、时间段、来源页面等。直接为每一对特征组合学习参数，会造成参数量巨大，很多组合还没有足够样本。

Rendle 在 2010 年提出 Factorization Machines（FM），用低维向量的内积表示特征之间的二阶交互：

\[
s(x)=w_0+\sum_i w_i x_i+\sum_{i<j}\langle v_i,v_j\rangle x_i x_j
\]

第一项是全局偏置，第二项描述单个特征，第三项描述两两交互。FM 不为每个特征对单独维护一个自由参数，而是为每个特征学习向量，通过向量内积共享统计信息。

矩阵分解与 FM 有一个重要联系：当输入只有用户 ID 和物品 ID 时，FM 的二阶交互就包含用户向量与物品向量的内积。加入上下文特征后，FM 可以进一步表达“用户 × 物品”“用户 × 设备”“物品 × 时间”等关系。

FM 的优势在于稀疏数据下的参数共享，局限是标准形式主要建模显式二阶交互。对于更复杂的非线性关系，需要引入神经网络或其他交叉结构。

## 六、DeepFM：把低阶记忆与高阶泛化放在一起

DeepFM 是一种面向 CTR 预测的模型，由 FM 分支和 DNN 分支组成。两条分支共享特征 Embedding：

```text
离散特征 → Embedding ──┬→ FM：一阶与二阶交互
                       └→ DNN：多层非线性交互
                               ↓
                         点击率或转化率预测
```

可以把模型写成：

\[
\hat y=\sigma\left(s_{FM}(x)+s_{DNN}(x)\right)
\]

FM 分支擅长捕捉稳定的低阶关系，DNN 分支通过多层非线性变换学习更复杂的高阶组合。Guo 等人在 2017 年的《DeepFM: A Factorization-Machine based Neural Network for CTR Prediction》中提出了这种共享 Embedding 的结构。

例如，用户 ID 与物品 ID 的组合可能反映长期偏好，物品类别与时间段的组合可能反映场景偏好，用户历史兴趣与当前来源页面的组合则可能表达即时意图。DeepFM 能够在同一模型中处理这些不同层次的交互。

DeepFM 通常更适合排序而不是全量召回。原因很直接：它的输入包含用户、物品和上下文的联合特征，往往需要针对每个候选执行一次前向计算。候选数量从几千缩小到几十或几百后，这种计算才比较容易满足线上延迟要求。

使用 DeepFM 也不代表特征工程消失了。模型仍然依赖合理的字段划分、行为序列构造、缺失值处理、特征时间一致性和线上线下特征对齐。它减少的是手工枚举交叉特征的工作，而不是数据治理和特征设计本身。

## 七、DIN 与 DCN：排序模型如何继续增强

### 1. DIN：让兴趣表示依赖候选

Deep Interest Network（DIN）针对用户行为序列提出了候选相关的兴趣激活机制。它不把用户所有历史行为简单平均，而是根据当前候选物品，对历史行为分配不同权重。

如果当前候选是夜景摄影教程，摄影相关历史应该获得更高权重；如果候选是海岛旅行攻略，旅行相关历史应该被激活。这样得到的用户表示会随着候选变化。

DIN 的优点是能表达多兴趣和候选相关性，代价是用户历史聚合需要与候选一起计算。这使它更适合排序阶段，也说明了召回模型和排序模型在结构上的根本差别：召回需要用户向量尽量独立生成，排序可以为每个候选做更细的交互。

### 2. DCN：显式学习特征交叉

Deep & Cross Network 及其后续版本 DCN-V2，通过交叉网络显式构造特征组合，同时保留深度网络的非线性表达能力。它关注的是如何更有效地学习特征交叉，而 DIN 关注的是如何从行为序列中提取当前候选相关的兴趣。

在排序实践中，DeepFM、DIN、DCN 可能承担不同职责：DeepFM 提供 FM 与 DNN 的联合基线，DIN增强行为序列建模，DCN增强显式交叉。选择哪个模型，应由误差分析和线上约束决定，而不是只根据模型名称判断。

## 八、把算法放回完整推荐链路

一个可操作的系统可以按下面的方式组织：

| 阶段 | 主要目标 | 可用方法 | 常见约束 |
|---|---|---|---|
| 多路召回 | 从全库找候选 | ItemCF、矩阵分解、双塔、热门、内容召回 | 延迟、覆盖、索引更新 |
| 粗排 | 快速缩小候选 | 线性模型、轻量 MLP、简化特征模型 | 特征数量和计算量受限 |
| 精排 | 预测候选相对价值 | FM、DeepFM、DIN、DCN、Transformer 类模型 | 特征一致性、延迟、稳定性 |
| 重排 | 优化列表整体效果 | 去重、多样性、MMR、规则约束 | 业务规则、供给平衡、用户体验 |

多路召回的结果不应只按分数简单拼接。不同通道的分数尺度可能不同，通常需要做归一化、分通道配额或训练统一的融合模型。还要记录每条候选来自哪个通道，以便分析每个通道对最终点击、观看和转化的贡献。

排序目标也不应只看点击率。对于视频，可以同时考虑播放完成度、有效观看时长和负反馈；对于电商，可以考虑加购、购买、退款和利润；对于内容平台，还要考虑作者生态、内容多样性和用户长期留存。多目标排序通常会先分别预测各目标，再按业务策略组合分数。

## 九、如何设计一条可验证的实验路线

推荐系统改造容易陷入“换一个更大的模型”的循环。更稳妥的路线是先建立清晰基线，再逐层增加能力。

第一步可以用热门、ItemCF 和矩阵分解建立召回基线，用简单的逻辑回归或 FM 建立排序基线。第二步引入双塔，比较向量召回相对于传统协同过滤的覆盖、延迟和长尾表现。第三步在候选集合稳定后加入 DeepFM，观察特征交互是否带来排序增益。第四步根据误差分析决定是否引入 DIN、DCN 或更复杂的序列模型。

每次实验都应明确回答一个问题：新增的模型能力解决了哪类错误？例如：

- ItemCF 召回不到新物品，是否需要内容或双塔召回？
- 双塔能找到相关候选，但相似内容过多，是否需要精排和重排？
- DeepFM 对短历史用户效果差，是否需要更好的序列表示？
- 排序模型离线指标提升，线上观看时长却下降，是否存在目标错配？

评估时需要区分召回指标和排序指标。召回可以关注 Recall@K、候选覆盖率、长尾覆盖和检索延迟；排序可以关注 AUC、LogLoss、NDCG、MRR 以及业务目标。线上还要观察延迟、错误率、负反馈、留存和分群表现。

尤其要明确负样本和评估候选集。把一个正样本与少量随机负样本放在一起计算的指标，不能等同于从全量物品中排序。Krichene 与 Rendle 在《On Sampled Metrics for Item Recommendation》中讨论了采样评估指标可能改变模型优劣关系的问题。因此，实验报告至少应写清候选范围、采样方式、时间切分和指标口径。

## 十、常见误区

**把未点击当成明确负反馈。** 用户没有点击，可能是没有曝光、没有注意到，也可能是位置和时间不合适。负样本需要结合曝光事实、采样策略和任务定义理解。

**把双塔当成万能排序模型。** 双塔的独立编码结构带来大规模检索效率，也限制了跨侧细粒度交互。它适合召回，不能自然替代所有精排模型。

**认为 DeepFM 自动解决冷启动。** 如果新物品只有一个从未训练过的 ID，模型仍然缺少可靠的 ID 表示。内容特征、类目特征、预训练向量和热门策略需要共同处理冷启动。

**只看离线 AUC。** AUC 能说明排序区分能力，但不一定代表用户会获得更好的列表。线上延迟、曝光位置、长期留存和列表多样性都可能改变最终结果。

**只比较模型，不比较数据和训练过程。** 负采样、时间切分、特征穿越、训练目标和线上特征延迟，往往比网络层数更容易造成实验结论失真。

## 结语

CF、矩阵分解、双塔和 DeepFM 可以看成一条逐步扩展的技术路线。CF 从邻居关系出发；矩阵分解把关系压缩到向量空间；双塔把向量匹配扩展到可检索的大规模召回；FM 和 DeepFM 则在候选集合上建模更加丰富的特征交互。

没有一种模型单独负责完整的推荐系统。工程上的关键是让每种模型处在适合它的阶段：用便宜且覆盖广的方法找候选，用能够表达复杂交互的模型排序，再通过重排处理列表整体效果。最终的判断标准也应落到完整链路：候选是否找得全，排序是否排得准，系统是否跑得稳，用户和业务是否获得长期价值。
